## 1. Executive summary

SmartPlant AI is an M.Tech Artificial Intelligence research prototype for interpreting plant-leaf photographs. The existing Streamlit application combines a **29-class MobileNetV3-Small CNN** with descriptive image-color/texture indicators, ranked predictions and CSV export. Its checkpoint-handling code uses a pinned SHA-256 and PyTorch safe loading. A separate **Android ONNX offline inference** implementation and professional mobile interface exist in source, with recorded CI evidence; full installation, airplane-mode, camera/gallery and real-leaf parity evidence on physical phones is not established by the reviewed repository documents. A proposed **50-class extension** has source discovery, inventory, provenance and guarded ingestion tools, but **no independently approved complete dataset, validated trained 50-class model or field-accuracy result**.

The repository now contains README onboarding improvements, `CONTRIBUTING.md`, `DISCOVERY_PACK.md` and structured issue templates from merged PR #15. GitHub's About description and homepage were observed populated on 24 November 2026; the repository's topic list was still empty when checked. An active "Protect Main Branch" ruleset targets the default branch and restricts deletions, non-fast-forward pushes and changes without pull requests. It does not currently require a passing CI status context or independent approving review.

**Bottom line:** This is a functioning research/application foundation, not a certified plant-disease diagnostic system or verified microcontroller TinyML product.

## 3. Work completed and source evidence

### 3.1 Web and 29-class model
- Streamlit interface at [SmartPlant AI demo](https://tinyguard-ai-rhqchfw8wkoqetj3zcwcsd.streamlit.app/), with browser-based JPG/PNG/WEBP upload, top-five predictions, charts and CSV export as described in `README.md`.
- Model implementation is in `smartplant/cnn.py`, trusted checkpoint handling in `smartplant/model_download.py`, and the web entry point in `app.py`.
- The current README documents **29** output classes, **160 × 160** center-cropped input and ImageNet normalization, plus descriptive green/yellow/brown, HOG and histogram features.
- The pinned checkpoint can be verified by `scripts/check_cnn_checkpoint.py`; that verifies load/inference integrity, **not** classification accuracy.
- A separate Random Forest/HOG baseline can be trained via `train.py`, but baseline metrics must be generated by an actual run and should never be substituted for CNN results.

### 3.2 Android Edge AI
- PRs [#5](https://github.com/dapperdude404/tinyguard-ai/pull/5), [#6](https://github.com/dapperdude404/tinyguard-ai/pull/6), [#7](https://github.com/dapperdude404/tinyguard-ai/pull/7) and [#8](https://github.com/dapperdude404/tinyguard-ai/pull/8) contain the offline Android/ONNX build and UI evolution.
- `android-edge/` holds the Kotlin/Gradle application. `EdgeClassifier.kt` handles model inference; `MainActivity.kt` handles the interface and image actions. The Android manifest in the checked commit contains **no INTERNET permission**.
- `scripts/export_smartplant_onnx.py` creates ONNX assets and verifies raw-logit parity against PyTorch on seeded synthetic inputs.
- `docs/ANDROID_EDGE_PHASE1.md` records passing CI for Android debug compilation and ONNX parity on **21 November 2026**. The associated artifact was labeled **UNTESTED**, deliberately not a production-signed release.
- `docs/ANDROID_V2_UI.md` describes camera/gallery handling, result presentation, local history and a confirmation-based clear action. These are implementation/documentation claims, **not** independently verified physical-device acceptance.
- `docs/SMARTPLANT_PHASE2.md` documents crop-aware mismatch review after an observed potato-vs-strawberry prediction error. The user-selected crop is not automatic crop recognition. Original probabilities remain unchanged by the review logic.

```text
              SMARTPLANT AI — CURRENT RESEARCH TRACKS
  ┌────────────────── Web / Cloud ──────────────────────┐
  Leaf photo → Streamlit → RGB/feature analysis → PyTorch
                              │               │
                              └──── 29 labels ┘
                               charts / CSV export
  └─────────────────────────────────────────────────────┘
  ┌───────────────── Android / Offline ────────────────┐
  Phone camera / gallery → preprocessing → ONNX Runtime
                                        → top-five result
                              optional crop-aware warning
                              local history
  └─────────────────────────────────────────────────────┘

  Future 50-class research:
  licensed sources → evidence review → strict dataset audit
     → grouped train/val/test → training → independent metrics
     → new model hash → ONNX export → separate device validation

  Separate legacy TinyGuard / TinyML experiments:
  anomaly / compact-model concepts → actual microcontroller tests
  (not proven by the Android or Streamlit paths)
```

**Required evaluation protocol:** dataset license/provenance table, original-image near-duplicate audit, grouped train/validation/test split, class frequency counts, per-class precision/recall, macro F1, confusion matrix, calibrated probabilities where justified, and failure-case records. Report each result only when obtained from a verifiable run with a fixed model, data snapshot and evaluation script. Avoid invented `95–100%` accuracy, generic “AI diagnosis,” or model score as medical/agronomic certainty.

### P2 — Reproducible 50-class data readiness
1. Review every source for copyright/license, disease terminology, class mapping and original leaf/farm provenance.
2. Complete strict image decoding, checksum and perceptual duplicate inspection.
3. Ensure the 50-class readiness gate fails when any required class/provenance is missing.
4. Do not train until a complete grouped dataset and independent test partition exist.

**Exit:** checked intake manifest, class-level counts, group-aware splits, reviewer signoff and approval to train.

### P3 — Research-grade 50-class validation
1. Train only on the approved dataset, preserve a complete environment and seeds.
2. Benchmark the proposed model separately from the current 29-class production pipeline.
3. Publish **actual** test metrics, calibration and error analysis; do not mix model versions.
4. Export only verified model artifacts with checksums and an independent deployment decision.

### P4 — Real TinyML, if microcontroller hardware is intended
Select a concrete MCU/board and runtime (for example TFLite Micro only when compatible), confirm ops and quantization, then benchmark flash, RAM, inference latency, energy and failure behavior on hardware. Keep this **separate from phone ONNX** and do not call the phone app an MCU deployment.
